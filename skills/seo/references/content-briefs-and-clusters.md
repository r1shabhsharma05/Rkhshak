# Content briefs and clusters

## Content briefs
A brief is a plan for a page that can outrank the current results — not a summary of them.

1. **Determine mode**: new page or improve-existing-page; page type (guide, how-to, comparison, review, landing, service).
2. **Fetch context**: the target URL if improving; the site's sitemap and structure for internal-link opportunities.
3. **Analyse SERPs**: for the top competitors, record headings, word count, and a score — then find the gaps:
   - Topic gaps: subtopics competitors miss entirely.
   - Depth gaps: topics covered but shallow.
   - Quality gaps: outdated info, no expert perspective, poor formatting.
4. **Classify intent**: Informational (learn), Commercial (research before buying), Transactional (ready to act), Navigational (looking for a specific site).
5. **Build the brief**: primary keyword, per-section word counts, competitor table, keyword placement guidance, meta tags, internal links, E-E-A-T requirements.

## Rules a brief must not break
- **Website relevance**: the topic must fit what the site is actually about. A page that wins the keyword and loses the visitor is a failure.
- **Information gain (non-negotiable)**: the brief must name something the page adds that competitors do not — original data, a first-hand test, an expert angle, a missing subtopic. Without it, the page is a rewrite.
- **Keyword placement**: primary keyword in title, H1, first paragraph, and a few headings — naturally, never stuffed. Search terms belong in sentences a human would type.
- **Meta tags**: title 50–60 characters, description 150–160, unique per page, carrying the primary keyword and a reason to click.
- **Internal linking**: link to the page from relevant existing pages and out from it to the pillar and sibling pages.

## SERP-overlap clustering
Cluster keywords by how much their search results overlap — shared results mean shared intent.

| Shared results (top 10) | Relationship | Action |
|---|---|---|
| 7–10 | Same post | Merge into a single target page |
| 4–6 | Same cluster | Group under the same spoke cluster |
| 2–3 | Interlink | Adjacent clusters, add cross-links |
| 0–1 | Separate | Different clusters, or exclude |

## Seed expansion (before clustering)
Related searches, "people also search for", People Also Ask questions, long-tail modifiers (best, how to, vs, for beginners, tools, examples, guide, template, mistakes, checklist), question variants (who/what/when/where/why/how), commercial modifiers (pricing, review, alternative, comparison, free, top). Classify intent; exclude navigational keywords (brand names, login) from clusters.

## Hub-and-spoke architecture
1. **Pillar**: the highest-volume, broadest-intent keyword with the most SERP overlap.
2. **Clusters**: 2–5 per pillar, each a subtopic area with 2–4 spoke posts.
3. **Templates by intent**: informational broad → ultimate guide; how → how-to; list → listicle; concept → explainer; compare → comparison; evaluate → review; rank → best-of; transactional → landing page.
4. **Word-count targets** per post, set from the SERP, not from habit.
5. **Cannibalisation check**: no two posts share the same primary keyword. If SERP overlap says they are the same post, merge them.
6. **Internal-link matrix**: every spoke links to the pillar (mandatory); spokes link to siblings in the same cluster; anchor text descriptive and varied — never exact-match repetition.

## Brief output format
Content Brief: [Primary Keyword] → Search Intent → Competitor Analysis (URL, headings, words, score, main gap) → Content Gaps → Winning Outline (per-section word counts) → Recommended Meta Tags → Unique Angle and Information Gain → E-E-A-T Requirements → Internal Linking Opportunities.
