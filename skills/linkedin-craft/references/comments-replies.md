# Comments and replies — draft, sweep, monitor, analyse (draft only)

Distilled from `linkedin-skills` (MIT bundle: comment-drafter, reply-handler,
thread-monitor, engager-analytics). Own words; reference files distilled,
not copied.

## Comment drafting
1. **Take the post.** The user provides the post URL or pastes the post text.
   Without a read layer, pasted text is the source — say so plainly; never
   claim to have read the live thread.
2. **Engage the post's actual point.** Quote or paraphrase the point, add one
   specific thought from the user's experience, and stop. A comment that
   could fit any post fits no post.
3. **Short, in the user's voice.** One to three lines unless the post earns
   more. No emoji stack, no generic praise, no pitch for the user's own work
   unless the post invited it.
4. **Return as a copy-paste block.** The owner posts it himself.

## Reply handling (threads)
- Reply to a comment — the user's or someone else's — from the comment text
  and the thread context. Keep the reply in the thread's register: answer the
  question asked, not the question wished for.
- **Thread sweep:** replying to an entire comment thread from just the post
  URL means one draft per comment, each engaging that comment's point.
  Present the drafts as a numbered list with the comment each answers; the
  owner approves each or the batch, then posts them himself.
- Never reply as the user to a comment the user has not seen. Show the draft
  with its target first.

## Thread monitoring
- Track which of the user's comments got author replies. Report: comment,
  author reply (or none), and what deserves a follow-up. A comment with no
  reply is data, not failure — say so and move on.
- Monitoring reads; it never posts. A follow-up is a new draft, approved
  before it exists anywhere live.

## Engager analytics
- Analyse who liked or commented on a post: audience segmentation by role,
  seniority, or interest — from the public engager list only.
- Report segments with counts and one-line reads ("hiring managers are
  engaging, founders are not"). No inference about private attributes; no
  contact without the owner's explicit word for that person.
- The read side may need the owner's read-side scraping account (free tier
  covers roughly a thousand fetches a month). With no read layer, ask the
  user to paste the relevant text — it costs nothing and reads the same.
