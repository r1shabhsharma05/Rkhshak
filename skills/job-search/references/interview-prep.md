# Interview prep — mocks, roasts, briefs, plans (prep only, never live help)

Distilled from `cracked` v1.3.0 (MIT, 19-skill interview-prep pack).
Own words; the pack's install paths, local data files, and website are not
carried over — the method below is what this skill preserves.

## What it covers
Timed mock DSA interviews, online-assessment sims, system-design and HR
rounds, resume roasts with ATS scores, company briefs, prep plans, rejection
reviews, and offer decoding. Pick the session by the user's ask:
- **Mock DSA interview** — timed, hidden edge cases, hire/no-hire scorecard.
- **OA sim** — timed assessment as real files, graded against hidden tests.
- **Pattern coach** — Socratic hints toward the pattern when stuck, never
  the answer.
- **Core viva** — rapid-fire OS, DBMS, networks, OOP, SQL with real query
  execution.
- **System-design mock** — high/low-level design, calibrated fresher to
  mid-level.
- **HR round** — behavioural practice scored on STAR structure, specificity,
  and length.
- **Defend-my-project** — cross-examination on the user's real project code,
  with a defence sheet of prepared answers.
- **Roast-my-resume** — brutal review with an ATS score and fabrication-free
  rewrites.
- **Resume blueprint / JD match** — what the resume should contain for one
  target company; how well it fits a pasted JD.
- **GitHub glow-up** — recruiter-eye audit of the profile and README.
- **Make-it-hireable** — upgrade a college project to production grade on a
  separate branch, in small reviewed steps.
- **Referral DM** — referral ask, hiring-post comment, recruiter DM, cold email.
- **Prep plan** — week-by-week plan from deadline, hours, and real weak spots.
- **Rejection review** — root-cause post-mortem with three drills.
- **Offer decode** — in-hand pay, red flags, negotiation draft.

## Running a session
1. **Load the profile first.** Read the candidate's real profile (skills,
   experience, target companies) at the start of every session. Ask only for
   missing fields, in one round of short questions.
2. **Follow the named session's rubric exactly** — its scoring, hint ladder,
   and scorecard format. Do not soften the rubric.
3. **Run the candidate's code for real** with the toolchain for their
   language, instead of guessing about it. Without the toolchain, say so and
   fall back to hand-tracing — never pretend a run happened.
4. **End with a scorecard** shown to the user and kept in a session journal,
   with weak-spot tags. If three or more earlier entries exist for the same
   session type, add one trend line under the scorecard.

## Honesty rules (hard)
- **Score like a real interviewer, not a cheerleader.** A top score is rare
  and earned.
- **Never fabricate the candidate's experience.** No invented metrics,
  projects, companies, or skills in resumes, messages, or answers. When a
  number would help, put `[N users]` and ask for the real value.
- **Label where company information comes from.** Community-reported
  questions are "frequently reported", never leaked; web findings cite their
  source; anything else is "typical of the archetype". Never call anything a
  company's official, leaked, or guaranteed question.
- **Practise only, never live cheating.** In a live proctored assessment or
  interview, decline to solve it and offer a debrief afterwards, or practice
  on the same pattern once it is over.
- **Missing tools are fine.** Say which sessions lose which feature instead
  of failing the session.
