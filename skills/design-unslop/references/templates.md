# Templates — themes, shapes, effects, and the Awwwards bar

## Deal 3 themes (Mode A, new pages)
Deal three themes that fit the prompt. The user picks one. Never self-pick. Re-deal only when asked. A theme is a material, not a plan: it never sets what the page contains or in what order. Where it and a shape or genre disagree on material, controls, or motion, the theme wins; the Floor and the user's own words beat both.

A theme carries: palette balance, type voice, surfaces, and its Range (the sections it makes without a photograph). Pick the theme whose material can carry the prompt (motion, photographs, code). Say which and why.

**Genre (silent, before the deal):** AI tool / generative / music / video / voice / dark / atmospheric → **atmospheric**; SaaS / enterprise / API / platform / developer tool / infra / B2B → **modern-minimal**; playful / fun / friendly / soft / kids / games / community → **playful**; otherwise **editorial** (holds most consumer and family prompts). Once a theme is dealt, its genre wins.

**Tone (ask the user):** pick an extreme — editorial, brutalist, soft, utilitarian, luxury, playful, technical, austere. "Clean and modern" is not a tone.

## Shapes (page structures)
Pick one shape per page, from the material: a page with pictures leads with them; a page about words carries type and facts (Long Document, Letter, Index-First, Manifesto). The shape follows the job — name what a visitor comes to do (subscribe, book, visit, attend, buy, try, sign up, hire, join, listen) and build the page from that category's anatomy, never from a default run of figures, steps, and an email band.

**Mirror test:** would a neighbouring prompt in the same category get this exact combination? If yes, change one decision and say which.

## Signature
The one thing a visitor would remember: the prompt's strongest real thing shown at its best (the photograph that is the place, the product doing its one job, a price set huge because it is the offer, a control to try). Make it in the theme's material, show it on the first screen. A number drawn as marks is a device, not a signature.

## Site effects (website-to-code — rebuild mechanisms, never copy art)
Four proven interactions, rebuilt from scratch. Copy one component out and it works. Bring your own art, credit the source site when shipping.
| # | Interaction | Source | What it does |
|---|---|---|---|
| 001 | Diagonal carousel | studioloop.com.br | Objects travel one shared diagonal, rotating as they go; lights flicker on as they pass centre |
| 002 | Image sphere | gionatannese.com + k95.it | 3D gallery on a sphere or endless helix; drag to orbit, scroll to roll/screw |
| 003 | Particle blob | vanlent.dev | One point cloud, seven displacement fields that crossfade, plus a frosted-glass shell |

**Rule:** these are sources to shortlist FROM, not a pick. Shortlist 3 options, the user picks. Never self-pick a design. Never lift the original sites' artwork, copy, or fonts.

## Awwwards quality bar (acceptance bar, never an award claim)
- **Art direction first:** write a compact direction before coding — visual thesis, hero focal asset, type hierarchy, color system, section sequence, motion narrative, smooth-scroll engine, Three.js decision, asset provenance plan.
- **Honest assets:** generate original hero/project imagery when it improves the concept, or use appropriately licensed media and keep provenance in the source. Never draw illustrations with model-authored SVG/CSS/canvas paths — use original generated or licensed transparent PNG cutouts. Photographs for every avatar (never initials, illustrated heads, faceless silhouettes, or generated people as real customers/staff/endorsers). Solar icons via Iconify for interface symbols. Iconify SVG Logos only for legitimate real-company marks. Logo Ipsum only for explicitly disclosed fictional brand specimens. Omit a logo wall when no honest proof exists.
- **Hero:** the first viewport is the strongest authored moment — clear message + CTA with original imagery, video, pointer-responsive interaction, or a justified Three.js scene. Composed GSAP intro. Navigation, message, and CTA readable before the animation completes. Static first frame complete without JS/media/WebGL/motion.
- **Motion:** GSAP primary. Exactly one smooth-scroll engine (Lenis or Locomotive, never both), connected to ScrollTrigger, refreshed after media/font changes, destroyed on cleanup. Bypass under `prefers-reduced-motion`. Choreograph section by section. Preserve an unsplit accessible name for staggered text. CSS for simple states, ScrollTrigger only for justified scrubbed/pinned sequences.
- **Three.js only with purpose:** spatial depth, texture transition, displacement, or pointer response that materially supports the art direction. One clear responsibility, subordinate to content. Cap pixel ratio, pause offscreen/hidden, throttle pointer, dispose everything. Static poster + replace canvas under reduced motion or WebGL failure.
- **Complete page:** responsive navigation, coherent section progression, concrete conversion content, final CTA, footer, robust form/control states, visible keyboard focus. Distinct art-directed idea, memorable first viewport, disciplined typography and spacing, intentional image crops, authored transitions, refined hover/focus/active/loading/disabled/error/touch/reduced-motion behavior.
- **Performance:** responsive media, lazy loading below the fold, bounded transforms, limited blur, capped canvas work, no continuously animated offscreen content.
- **Reject:** generic gradient blobs, ornamental bento grids, glass applied everywhere, stock component layouts, fake testimonials, invented partnerships, logo-wall theater, motion with no narrative role.
- **Validate before handoff:** production build green; desktop + mobile sizes; keyboard navigation, visible focus, touch, no-JS content, static media fallbacks, reduced-motion; one smooth-scroll engine only; search rendered content and source for placeholders, copied identity, unsupported claims, misleading logos, uncredited media, inaccessible split text. Report the art direction, asset sources, motion stack, Three.js decision, validation performed, and remaining limitations.
